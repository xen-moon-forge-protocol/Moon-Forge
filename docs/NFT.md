# Moon Forge Artifacts

Metaplex Core NFTs, collection PDA `["collection"]` of program `57UE1U1t23ztg2noLp8pcpGW1B1Xw25rLH6ra9Mchea9`, update authority = program PDA `["artifact_authority"]` (no human key; the program itself is upgradeable during the test period — see [SECURITY.md](../SECURITY.md)). Royalty plugin on the collection: 5% to the architect on secondary sales, paid only where marketplaces honor it.

Dynamic price (`artifacts.rs::current_price / next_price`): +5% per forge; ÷1.05 (−4.76%) per full week without a forge; never below the base price, never above 100× it. The buyer signs `max_price`, so a price move can only make the transaction fail, never charge more. Recycling does not change the price.

"Max alive": a cap on Artifacts alive at the same time. Recycling frees a slot, which can be forged again. Asset addresses are PDAs `["asset", tier, serial]`; serials only grow.

## Lifecycle

- **Forge** (`forge_artifact(tier, serial, max_price)`): the price paid is split 50% floor (kept in the `ArtifactRecord` PDA) / 40% reward pool / 5% Burn Lottery / 5% architect. (The 5% forge cut is not a royalty; the royalty is the separate 5% on secondary sales.)
- **Recycle** (`recycle_artifact`): the holder burns the NFT through Moon Forge and receives the floor + record rent; the slot is freed.
- **Forge Drops** (`claim_drop`): 10% of every epoch budget (at most 100 XNT) is drawn among that epoch's XEN burners as Lunar Dust — part of their own epoch reward, not extra. Each leaf's expected drop value is its share of that reserve; it wins with probability (value ÷ 5 XNT), and at or above 5 XNT it always wins and the whole value becomes the floor. Odds are linear (splitting never changes your expected drop value) and use the hash of the first block at or after the publish slot + 4, sealed permissionlessly; if nobody seals within ~512 slots the drops are cancelled and the reserve returns to the pool. Origin "Forge Drop". If 600 Lunar Dust are alive, `claim_drop_xnt` pays the same value in XNT. A drop must be received within the epoch's 90-day window (anyone can deliver it; the Artifact always goes to the player in the leaf). See the whitepaper, section 3.1.
- **Orphans** (`reclaim_orphan`): if an Artifact is burned outside Moon Forge, anyone can send its floor to the reward pool and free the slot.
- **Chips** (`claim_artifact_chips`): once per week per Artifact, by its current holder — 5 / 15 / 40 / 150 by tier. Weeks are `unix time / 604800`, so they reset on Thursdays 00:00 UTC; a missed week does not accumulate.
- **Boost**: at each epoch the oracle snapshots live holders. Only an Artifact held by the **same owner at both the previous and the current epoch snapshot** counts (no flash forging or renting for the snapshot; in the first epoch no boost applies), and only the best one per wallet. A boost raises your share of that epoch, never the epoch total: a burner alone gains nothing from it.
- **Duel**: holding a live Artifact of **any** tier is the ticket to the Duel arena (checked when creating and when joining). The element you play is free (any of the four), chosen per duel and hidden by commit-reveal; it does not depend on which Artifacts you hold. Lunar > Void > Solar > Cosmic > Lunar; same or opposite element = draw.

## On-chain attributes (readable by any project)

Each asset carries a Core `Attributes` plugin: `Tier`, `Element` (thematic, tied to the tier; Duel elements are chosen freely), `Burn Boost`, `Weekly Chips`, `Floor XNT`, `Origin` (Forged / Genesis Airdrop / Forge Drop), `Serial`, `Recyclable`. Other X1 projects can grant utility to holders by reading the asset owner and these attributes, or the `ArtifactRecord` PDA.

## Metadata

`https://xen-moon-forge-protocol.github.io/Moon-Forge/nft/<tier_slug>/<variant>.json` (variant = serial % variants), plus `nft/collection.json`. Generated by `scripts/nft-metadata/generate-metadata.mjs`; images 1024×1024 JPEG in `nft/images/<tier_slug>/`.

Names and URIs are written on-chain at mint time by the program (`{Tier} #{serial+1}`, URI as above), so the JSON describes the variant artwork and the on-chain `Attributes` plugin carries the per-asset facts (exact floor, origin, serial).

Artifacts do not exist before someone mints them: the collection is created once by `init_artifacts` after the program upgrade, and each Artifact is created when it is forged, airdropped or dropped. "Max alive" is a cap, not a pre-minted stock.

## Genesis airdrop

Up to 120 Lunar Dust without floor. The architect publishes the list once (`set_airdrop_root`, one-time and final); each listed wallet claims with its Merkle proof from `frontend/public/airdrop/airdrop.json` (built by `scripts/airdrop/build-airdrop.mjs`). Only the first 120 claims succeed; the claimant pays the account rent, and a Lunar Dust slot must be free. Leaf = `keccak("MOONFORGE_V2_AIRDROP" ‖ wallet)`.

**Status: draft, not published on-chain.** The current file (root `ec3e6ae5bba79664bc86c77d3ad8a9b2e7e20b233adeb7a4686058f96019f171`) contains the 444 unique withdraw authorities of active X1 vote accounts on 2026-10-07 (the people who run X1 validators), excluding foundation-scale validators. Before `set_airdrop_root` it will be rebuilt to add Genesis supporters (see [SUPPORT.md](SUPPORT.md#genesis-supporters)), so the final root will differ. Anyone can rebuild the lists from public data:

```bash
node scripts/airdrop/collect-validators.mjs > validators.txt
node scripts/airdrop/collect-donors.mjs > donors.txt
cat donors.txt validators.txt > wallets.txt && node scripts/airdrop/build-airdrop.mjs wallets.txt
```
